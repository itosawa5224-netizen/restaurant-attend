# ユーザーインターフェース


#### ・前提：システム構成
本システムでは、<ins>*タブレット6台*</ins> を用いて以下のようなシステム構成での店舗運営を想定する。

| 用途 | 使用者 | 台数 | 概要 |
|---|---|---:|---|
| 受付用 | 来店客 | 1台 | 店舗入り口付近に設置し、来店客の操作で 「名前」「人数構成」などの情報を登録する |
| フロアリーダー用 | フロアリーダー | 1台 | ・フロアリーダーが常に持ち歩き、フロア状態や待機客一覧を確認する <br>・フロアリーダーの操作で他端末にバッシング指示を共有する|
| フロア配置用 | 全ホールスタッフ | 3台 | 店内３ヶ所に適宜配置し、バッシング完了次第、スタッフの操作で該当席のテーブル状態を”バッシング待ち → 案内可能”に更新する |
| レジ配置用 | 全ホールスタッフ | 1台 | レジ近くに配置し、お会計が完了次第、スタッフの操作で該当席のテーブル状態を”利用中 → バッシング待ち”に更新する |
<br>

 ### 工夫した点

 **受付用画面:**
 - 「待機客一覧を表示する画面」を起点にすることで、従来のウェイティングボード（紙の受付表）のように、受付前の利用客が "この店は今どれくらい並んでいるのか" を視覚的に確認できるようにした。
 - 「起点画面」→「入力画面」→「入力内容確認・受付順付与画面」→ 戻る　という画面遷移するスタイルにすることで初めてシステムを利用する来店客でも扱いやすくした。

 **フロアリーダー用画面：**
 - 待機客一覧とフロア状況を一画面にすることで、画面遷移や複雑なボタン操作による煩わしさを軽減し、繁忙時にもスムーズに扱えるようにした。
 

 **ホールスタッフ用画面：**
 - フロア状況を一画面にすることで、画面遷移や複雑なボタン操作による煩わしさを軽減し、繁忙時にもスムーズに扱えるようにした。

 **システム全体**
 - 受付用 / フロアリーダー用 / ホールスタッフ用 の画面ごとにURLを分けることによって、誤操作などによる他ページへのアクセスを極力防げるようにした
